# boot-slapper

Cross-platform onboarding for Claude Code against a third-party provider. Design: `docs/superpowers/specs/2026-09-09-boot-slapper-design.md`.
Plans: `docs/superpowers/plans/` (Phase 1 engine, Phase 2 artifacts + TUI + capture + shims; Phase 3 desktop + cutover staging (`docs/cutover/`)).
Spikes: `docs/spikes/` — S1/S2 (2026-09-10) settle where the Phase 3 desktop artifacts write: the per-user `Claude-3p/configLibrary/` document (inference + `managedMcpServers`), never user defaults or `claude_desktop_config.json`. S3 (2026-09-17, JCB-L-T000692): on a Cornell-managed Windows box `HKLM\SOFTWARE\Policies\Claude` sets 16 keys, so `desktop-inference`/`desktop-mcp` are blocked by policy and "green" is unreachable there; `desktop-skills` still works. Gate 2's Windows box is therefore **`yogaNovo`** (unmanaged, personal, arm64) — spec §6 gate table and `docs/cutover/gate-2-runbook.md` amended 2026-09-17.

## Rules that are not obvious from the code

- `src/engine/` and `src/artifacts/` never import `src/ui/`. Ink/React only under `src/ui/tui/`; `model.ts` and `prompter.ts` stay renderer-free.
- `detect` / `verify` / `capture` never write; `tests/unit/artifacts/contract.test.ts` enforces it with an exec allowlist — extend the allowlist when an artifact gains a read-only probe.
- Secret values never touch argv, events, logs, or bundles. Child processes get them on stdin or in a mode-600 file they own (`~/.mct/config.json`). A `set` failure must not quote PowerShell's stderr: an error record echoes the offending source line, which is the `PasswordCredential(...)` call carrying the plaintext (`tests/unit/engine/secrets.test.ts` asserts this).
- **`PasswordVault.Add` must be the last statement in the script — nothing after it, and never an `exit` reached through a `try`.** The vault commits asynchronously; an `exit` right after `Add` kills the process mid-commit and the credential is silently lost with exit code 0. This made `bs secrets set` a no-op on Windows for a week (S4, 2026-09-18: deterministic, 5/5, with `set` reporting success and `get` then saying "missing"). `set` now reads the value back in a fresh process and throws if it is absent — a store that cannot confirm its own write must say so. **Corollary: no Windows secret-store result recorded before 2026-09-18 is trustworthy**, including S3's Cornell-box doctor reds; macOS is unaffected (`security -i`, never had the pattern).
- `desktop-inference` refuses to write the credential helper when the secret store is empty *and* the applied entry is currently authenticating some other way (static key, or a foreign/IT helper) — that swap takes inference down on a working box, which is worse than not improving it. A box with nothing to lose is deliberately not blocked, so a fresh onboard cannot stall. It blocks rather than warns because apply steps run unattended under `--auto`.
- Windows: never spawn `.cmd`/`.bat` directly (see `npmArgv` in `src/artifacts/mct.ts`); build paths with `pj(env.os, …)`.
- Cutover state (spec §6): `bootstrap.sh` and `claude-gw.zsh` stay live until gate 2. Only `bs env | plan | doctor | capture` are meant to touch a real box before then.
- Desktop artifacts write exactly one Claude Desktop config-library entry (named `boot-slapper`, id in `~/.config/boot-slapper/desktop.json`) and only the Cowork skills they copied (hashes in the same sidecar). Foreign entries, skills and manifest rows are reported, never edited. Quit Desktop before `apply`; the app reads the library at launch.
- The *applied* config-library entry is what Desktop and Cowork read, so `desktop-mcp` and `desktop-skills` read it (`appliedEntry`) whether or not it is ours; `ourEntry` is only for writing. When `desktop-inference` adopts a foreign applied gateway entry, `desktop-mcp` is `blocked` with an in-app instruction, never writes servers anywhere, and `desktop-mcp` needs the same `baseUrl` option as `desktop-inference` to know that. Applying a configuration from inside Desktop (the in-app window's *Apply Changes* / choosing the configuration) re-serializes the applied entry from the window's full form model (default keys added, `oauth: true` → `{ mode: "dcr" }`) and relaunches; a plain quit-and-relaunch and the OAuth token save do not touch the library (tested 2026-09-16). So `desktop-mcp` compares servers with `sameServer` (oauth by presence) and keeps the app's oauth object when it rewrites.
- Desktop gets secrets only through helper executables (`~/.config/boot-slapper/desktop-*.sh|.ps1`, mode 700) that print the value from the secret store; `desktop-inference` verify sends the key as an in-process header to `GET /v1/models` and never logs it.
- **A hidden prompt must still hand readline the real prompt string.** `ask()` in `src/ui/prompt.ts` used to pass `""` and write the prompt by hand, so readline — believing its prompt was empty — redrew an empty line over it (`ESC[1G ESC[0J`: cursor to column 1, erase to end of screen). On most terminals the write and the erase raced and the text usually survived; in Windows PowerShell the erase won every time, so `bs secrets set` waited at a blank line with no visible prompt and looked like it had exited. Now readline owns the prompt and `_writeToOutput` echoes any write carrying it, collapses a newline write to a bare newline, and drops the rest (the typed characters). `ttyPrompter(streams?)` takes injectable streams so `tests/unit/ui/prompt.test.ts` can assert both halves — prompt visible, secret not echoed — against a fake tty; verified by reverting the fix on a scratch copy and watching the test fail.

- **macOS fresh-entry route, verified on `mac-studio` (the spec §6 second Mac; Desktop 2.7032.0, arm64, personal, login `alex`) 2026-09-23/24:** `desktop-inference` wrote the first `boot-slapper` entry on a Mac that had never run 3P, and the owner's first in-app *Apply Changes* re-serialized it exactly as the Windows and adopt-route boxes had shown — default keys added, `oauth: true` → `{ mode: "dcr" }` — **and dropped two keys we own: `inferenceGatewayAuthScheme` and `inferenceCredentialHelperTtlSec`.** Inference kept working through the helper (`running helper` → `helper ok`, 14 models discovered, `mecp` connected with 97 tools), so their absence is the app default. `docSatisfies` in `src/artifacts/desktop-inference.ts` therefore reads an app-dropped key as its default (`APP_DEFAULTED`) instead of calling the entry drifted; before that the doctor said "not configured for the gateway" on a working box and every onboard would have rewritten what the next in-app apply undid. `merged()` still writes both keys. This closes the runbook's "whether a `bs`-written entry survives an in-app apply intact" question: it does not, and it does not need to. **Two hostname lessons from the same box:** macOS with no `scutil` `HostName` takes `uname -n` from the reverse PTR of its current address, so the label flipped overnight from `mac-studio` to `alexsmacstudio` (the PTR the LAN resolver generated from the computer name) and orphaned the memory device config; the fix is the fleet's WSL one — `DEVICE_LABEL` in the gitignored `~/.claude/settings.local.json` `env` block, which `resolveLabel`, `bootstrap.sh --doctor` and `sync-memory` all honor. And the fleet slug is `mac-studio-m5-max` (MeCP device, `mct` device id, and the device token's `--device`, all three the same), mapped from the label in the profile's `deviceIds`. A global `bs` (`npm link`, `npm i -g`) was a silent exit-0 no-op until `src/main-guard.ts`: Node resolves symlinks for ESM, so `import.meta.url` never equalled the raw `argv[1]` link path.
- **`mecp-api-key` and `mecp-device-token` are different credentials and the names are not redundant.** A device token is a JWT (`mecp/scripts/mint-device-token.ts`: `createJwt("device", { device, scope }, …)` — per-device, ≤366-day expiry, revocable via `MECP_DEVICE_DENYLIST`); the master `API_KEY` is a short non-JWT string the mint script says devices should never hold. **Both install to the same path, `~/.config/mecp/api_key`, so only JWT shape tells them apart** — which is how a suspected master key sat on `yogaNovo` unnoticed from 2026-08-06 to 2026-09-18. Never satisfy a missing `mecp-device-token` by copying whatever is in that file into the vault; mint a scoped device token instead, install it over the file, then `bs secrets set mecp-device-token`. **Cleared on `yogaNovo` 2026-09-18** — the file now holds the write-scoped device token (199-char JWT), verified by effect rather than inspection: the SessionStart hook run end-to-end logged `identity: fetched OK (6796 bytes), cache refreshed`, a live authenticated fetch, where an immediate second run logged only a cache hit. Note the two paths never overlapped — the file feeds the SessionStart context hook alone, while `~/.claude/mcp/gateway.json` authenticates from `MECP_DEVICE_TOKEN` out of the OS vault — so the master's blast radius was the per-session context fetch. **The trap itself is still armed on every other box**: no reader inspects shape, and `bs secrets check` reports only `present`/`missing`, which was true and useless for six weeks. Fix filed as MeCP `project:dotclaude/mecp-key-file-shape-check`.
- **Device tokens are read-only only by *default*; `--scope write` gets the full MCP tool surface.** Worth stating because the opposite is easy to assume (the work item is named `mecp-readonly-session-token-and-rotation`). `api/mcp.ts` filters tools *only* when `principal.scope === "read"`; `api/_lib/mcp-auth.ts` honors a `scope: "write"` claim as `{ scope: "write", device }`, and `api/__tests__/mcp-auth-device.test.ts` covers it. A write device token is therefore sufficient for boot-slapper's `mecp` server on both surfaces — the only thing it cannot reach is `/api/api-usage/*`, which stays master/OAuth-only. So there is no "read-only token vs master key" tradeoff to make. Minting needs the master in env, which can be done on any box that has it: `API_KEY=… npx tsx scripts/mint-device-token.ts --device <box> --scope write`. **Confirmed empirically on `yogaNovo` 2026-09-18 22:22** with a freshly minted `--device yoga-novo --scope write` token in the vault: `[custom3p-mcp-headers] resolved { server: 'mecp', headerNames: ['Authorization'] }` then `[custom3p-mcp] server connected { name: 'mecp', toolCount: 97 }` — **97 tools, the same count as the Mac**, so the read-only filter did not run and the write scope is real. The `headersHelper` path is now proven on Windows with a live credential, and Desktop reconnected on its own retry cycle without a relaunch. `desktop-mcp` verify is fully green (both servers, helper current, token present), and the Desktop half of `open-brain-auth` turned ✓ unprompted.

- `desktop-inference` never writes `disableDeploymentModeChooser`; the owner keeps the claude.ai option on JCB-AL-ACA34. The second Mac (`mac-studio`) has arrived and is on the gateway; decide whether it is gateway-only and, if so, add the profile option that sets it `true` there.
- `MIN_DESKTOP_VERSION` is `1.19367.0`, but S2 records the `managedMcpServers` 3P scope as ≥`1.2581.0` — a different threshold, and these version strings do not order the way semver suggests. Nothing is blocked today (`2.2553.0` clears both), so the floor may simply be checking the wrong thing. Noted in S4, not chased.
- `bs capture` reads bundle files as UTF-8 text; extend `Io.readFile` to bytes if dotclaude ever tracks a binary.
- Interactive `project-memory` re-offers a guessed-but-declined memory dir on every run; map it by hand (or accept) to silence it.
- TUI Ctrl+C: Ink swallows SIGINT in raw mode and `runTui` resolves 130, so a child `git clone` / `npm install` started by an artifact keeps running after `process.exit`; headless mode kills the process group. Track the live child in `RealIo` and kill it on exit, or document the difference.
- `plugins`: `claude plugin install` runs without `-y` on purpose — a marketplace-declared install command is not auto-accepted headlessly; the CLI's error names the flag, and the owner runs that one install by hand. Revisit if a listed plugin ever declares one.
- `mct`: the activate step reports ✓ when it soft-skips (old node, no device id, no token) and leaves the explanation in a warn note; `verify` then says "not activated". A distinct step outcome for "skipped" would read better.
- TUI: long check messages wrap at the terminal width and the continuation lines lose the four-space indent (`components.tsx` — Ink `Text` `wrap="truncate-end"` or a hanging indent). MeCP `project:boot-slapper/tui-output-cosmetics`.
- Headless onboard prints each artifact's detected state twice — once from the live reporter (`artifact:detected`), once from `renderPlanText` in `cli.ts`; drop one. Same MeCP item.
- `open-brain-auth`'s Code-side hint (`CODE_HINT` in `src/artifacts/open-brain-auth.ts`: "/mcp → openbrain → Authenticate") only works in a `claude-gw` session: the `openbrain` server lives in the launch-scoped `~/.claude/mcp/gateway.json`, so a plain `claude` session's `/mcp` has no such entry and the owner authenticates the wrong (claude.ai-hosted) connector. Seen 2026-09-19 on JCB-AL-ACA34. Say "in a claude-gw session" in the hint.
- `tests/parity/doctor-parity.test.ts` runs both doctors with a blocking `spawnSync` that takes ~66 s; vitest's worker cannot answer the main process's `onTaskUpdate` RPC meanwhile and prints `Timeout calling "onTaskUpdate"` as an unhandled error on every run, passing or failing. The verdict is unaffected, but the line reads like a failure. Make the spawn async (`spawn` + await) or raise the worker RPC timeout. Seen 2026-09-19 on JCB-AL-ACA34.
