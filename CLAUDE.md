# boot-slapper

Cross-platform onboarding for Claude Code against a third-party provider. Design: `docs/superpowers/specs/2026-09-09-boot-slapper-design.md`.
Plans: `docs/superpowers/plans/` (Phase 1 engine, Phase 2 artifacts + TUI + capture + shims; Phase 3 desktop + cutover staging (`docs/cutover/`)).
Spikes: `docs/spikes/` — S1/S2 (2026-09-10) settle where the Phase 3 desktop artifacts write: the per-user `Claude-3p/configLibrary/` document (inference + `managedMcpServers`), never user defaults or `claude_desktop_config.json`. S3 (2026-09-17, JCB-L-T000692): on a Cornell-managed Windows box `HKLM\SOFTWARE\Policies\Claude` sets 16 keys, so `desktop-inference`/`desktop-mcp` are blocked by policy and "green" is unreachable there; `desktop-skills` still works. Gate 2's Windows box is therefore **`yogaNovo`** (unmanaged, personal, arm64) — spec §6 gate table and `docs/cutover/gate-2-runbook.md` amended 2026-09-17.

## Rules that are not obvious from the code

- `src/engine/` and `src/artifacts/` never import `src/ui/`. Ink/React only under `src/ui/tui/`; `model.ts` and `prompter.ts` stay renderer-free.
- `detect` / `verify` / `capture` never write; `tests/unit/artifacts/contract.test.ts` enforces it with an exec allowlist — extend the allowlist when an artifact gains a read-only probe.
- Secret values never touch argv, events, logs, or bundles. Child processes get them on stdin or in a mode-600 file they own (`~/.mct/config.json`). A `set` failure must not quote PowerShell's stderr: an error record echoes the offending source line, which is the `PasswordCredential(...)` call carrying the plaintext (`tests/unit/engine/secrets.test.ts` asserts this).
- **`PasswordVault.Add` must be the last statement in the script — nothing after it, and never an `exit` reached through a `try`.** The vault commits asynchronously; an `exit` right after `Add` kills the process mid-commit and the credential is silently lost with exit code 0. This made `bs secrets set` a no-op on Windows for a week (S4, 2026-09-18: deterministic, 5/5, with `set` reporting success and `get` then saying "missing"). `set` now reads the value back in a fresh process and throws if it is absent — a store that cannot confirm its own write must say so. **Corollary: no Windows secret-store result recorded before 2026-09-18 is trustworthy**, including S3's Cornell-box doctor reds; macOS is unaffected (`security -i`, never had the pattern).
- `desktop-inference` refuses to write the credential helper when the secret store is empty *and* the applied entry is currently authenticating some other way (static key, or a foreign/IT helper) — that swap takes inference down on a working box, which is worse than not improving it. A box with nothing to lose is deliberately not blocked, so a fresh onboard cannot stall. It blocks rather than warns because apply steps run unattended under `--auto`.
- Windows: never spawn `.cmd`/`.bat` directly (see `npmArgv` in `src/artifacts/mct.ts`); build paths with `pj(env.os, …)`.
- Cutover state (spec §6): `bootstrap.sh` and `claude-gw.zsh` stay live until gate 2. Only `bs env | plan | doctor | capture` are meant to touch a real box before then.
- Desktop artifacts write exactly one Claude Desktop config-library entry (named `boot-slapper`, id in `~/.config/boot-slapper/desktop.json`) and only the Cowork skills they copied (hashes in the same sidecar). Foreign entries, skills and manifest rows are reported, never edited. Quit Desktop before `apply`; the app reads the library at launch.
- The *applied* config-library entry is what Desktop and Cowork read, so `desktop-mcp` and `desktop-skills` read it (`appliedEntry`) whether or not it is ours; `ourEntry` is only for writing. When `desktop-inference` adopts a foreign applied gateway entry, `desktop-mcp` is `blocked` with an in-app instruction, never writes servers anywhere, and `desktop-mcp` needs the same `baseUrl` option as `desktop-inference` to know that. Applying a configuration from inside Desktop (the in-app window's *Apply Changes* / choosing the configuration) re-serializes the applied entry from the window's full form model (default keys added, `oauth: true` → `{ mode: "dcr" }`) and relaunches; a plain quit-and-relaunch and the OAuth token save do not touch the library (tested 2026-09-16). So `desktop-mcp` compares servers with `sameServer` (oauth by presence) and keeps the app's oauth object when it rewrites.
- Desktop gets secrets only through helper executables (`~/.config/boot-slapper/desktop-*.sh|.ps1`, mode 700) that print the value from the secret store; `desktop-inference` verify sends the key as an in-process header to `GET /v1/models` and never logs it.

Final entry is pure flat v1 with `inferenceCredentialKind: "helper-script"`. `openbrain`'s `oauth` came back as `{ mode: "dcr" }` — written as `true`, normalized by the app — so `sameServer`'s oauth-by-presence rule is now confirmed on Windows too. Taking ownership of the app-authored applied entry works by renaming it `boot-slapper` in `_meta.json` (`ourEntry` falls back to the name when no sidecar id matches); `bs onboard` then pins the id in the sidecar. **`inferenceGatewayApiKey` is still in the entry in plaintext** — `merged()` only overwrites `OWNED` keys by design, so boot-slapper never deletes what it did not write, but the old static key now sits beside the helper meant to replace it and the app may still prefer it. Rotating the Cornell key is therefore the only way to prove the helper is the live path; it is also still in `claude_desktop_config.json`'s `cornell_secure_tools` argv.
- `desktop-inference` never writes `disableDeploymentModeChooser`; the owner keeps the claude.ai option on this Mac. A gateway-only box may want it `true` — profile option to add when the second Mac arrives.
- **`mecp-api-key` and `mecp-device-token` are different credentials and the names are not redundant.** A device token is a JWT (`mecp/scripts/mint-device-token.ts`: `createJwt("device", { device, scope }, …)` — per-device, `read`/`write`, ≤366-day expiry, revocable via `MECP_DEVICE_DENYLIST`); the master `API_KEY` is a short non-JWT string the mint script says devices should never hold. **Both install to the same path, `~/.config/mecp/api_key`, so only JWT shape tells them apart** — which is how a suspected master key sat on `yogaNovo` unnoticed from 2026-08-06 to 2026-09-18. Never satisfy a missing `mecp-device-token` by copying whatever is in that file into the vault; mint a scoped device token instead (`--device <box> --scope write`), install it over the file, then `bs secrets set mecp-device-token`. A shape check where that file is read would stop this recurring.
- `MIN_DESKTOP_VERSION` is `1.19367.0`, but S2 records the `managedMcpServers` 3P scope as ≥`1.2581.0` — a different threshold, and these version strings do not order the way semver suggests. Nothing is blocked today (`2.2553.0` clears both), so the floor may simply be checking the wrong thing. Noted in S4, not chased.
- `bs capture` reads bundle files as UTF-8 text; extend `Io.readFile` to bytes if dotclaude ever tracks a binary.
- Interactive `project-memory` re-offers a guessed-but-declined memory dir on every run; map it by hand (or accept) to silence it.
- TUI Ctrl+C: Ink swallows SIGINT in raw mode and `runTui` resolves 130, so a child `git clone` / `npm install` started by an artifact keeps running after `process.exit`; headless mode kills the process group. Track the live child in `RealIo` and kill it on exit, or document the difference.
- `plugins`: `claude plugin install` runs without `-y` on purpose — a marketplace-declared install command is not auto-accepted headlessly; the CLI's error names the flag, and the owner runs that one install by hand. Revisit if a listed plugin ever declares one.
- `mct`: the activate step reports ✓ when it soft-skips (old node, no device id, no token) and leaves the explanation in a warn note; `verify` then says "not activated". A distinct step outcome for "skipped" would read better.
- TUI: long check messages wrap at the terminal width and the continuation lines lose the four-space indent (`components.tsx` — Ink `Text` `wrap="truncate-end"` or a hanging indent). MeCP `project:boot-slapper/tui-output-cosmetics`.
- Headless onboard prints each artifact's detected state twice — once from the live reporter (`artifact:detected`), once from `renderPlanText` in `cli.ts`; drop one. Same MeCP item.
- `tests/unit/shims.test.ts` flakes on Windows (~1 run in 4, either test): it shells out to `bash -n` / `powershell [scriptblock]::Create` to syntax-check the shims, and a cold `powershell` spawn can exceed vitest's 5 s default `testTimeout`. Not a regression and not visible on macOS — give those two tests an explicit longer timeout, or gate the spawn behind a warm-up. Found 2026-09-17 on JCB-L-T000692.
